[id="audit-logging_{context}"]
= {registry} audit events

:_mod-docs-content-type: ASSEMBLY

[role="_abstract"]
{registry} writes one audit event for every REST request that changes data, every request that authentication or authorization denies, and every call to a read operation that is audited on purpose, such as a data export.
Each event is one JSON object on one log line, so any log shipper can collect and parse it.

[id="audit-logging-scope_{context}"]
== Which requests produce an event

:_mod-docs-content-type: CONCEPT

[role="_abstract"]
The event is written once per HTTP request, after the response status is known, for every API that {registry} serves: the Core Registry API v2 and v3, the Confluent Schema Registry compatibility API v7 and v8, the Apache Iceberg REST catalog, the MCP Registry API and the `/.well-known` discovery endpoints.

A request produces an event when one of these conditions holds:

* It uses `POST`, `PUT`, `PATCH` or `DELETE`, whether it succeeds or fails.
* It is denied with `401 Unauthorized` or `403 Forbidden`, whatever its HTTP method.
* It calls a read operation that is always audited. Today these are the `exportData` operations of the v2 and v3 APIs.

A successful read produces no event.
A few operations use `POST` or `PUT` but change nothing, for example searching by content, looking up a schema by its content, checking compatibility, canonicalizing content and rendering a prompt template.
They produce an event only when they are denied.

An event is written only for requests that reach a REST endpoint.
Requests rejected before that point, such as a request for an unknown path, produce no event.

Every response for which an event is written carries the event identifier in the `Audit-ID` response header.
A browser client on another origin can read the header only if it is added to the exposed headers of the CORS configuration (`quarkus.http.cors.exposed-headers`).

[id="audit-logging-destination_{context}"]
== Where events are written

:_mod-docs-content-type: CONCEPT

[role="_abstract"]
Events are written at `INFO` level to the `io.apicurio.registry.audit.events` logger.
With the default configuration that logger writes to the console with the other {registry} log output.
The log line contains the JSON object as its message.

To send the events to their own destination, configure a handler for the category, for example a file handler:

[source,properties]
----
quarkus.log.handler.file.audit.enabled=true
quarkus.log.handler.file.audit.path=/var/log/apicurio/audit.log
quarkus.log.handler.file.audit.format=%s%n
quarkus.log.category."io.apicurio.registry.audit.events".handlers=audit
quarkus.log.category."io.apicurio.registry.audit.events".use-parent-handlers=false
----

The category is a sibling of the per-resource authorization denial logger,
`io.apicurio.registry.audit.authz`, whose `authz.denied` lines are not JSON, so a handler on the events
category receives only the JSON events.

[id="audit-logging-fields_{context}"]
== Event fields

:_mod-docs-content-type: REFERENCE

[role="_abstract"]
The field names follow the Kubernetes `audit.k8s.io/v1` `Event` where an equivalent exists.
Fields with no value are omitted.

.Audit event fields
[%header,cols="2,1,5"]
|===
|Field |Type |Description

|`apiVersion`
|string
|Version of the event format, `audit.registry.apicur.io/v1`.

|`kind`
|string
|Always `Event`.

|`level`
|string
|Always `Metadata`. Events never contain a request or response body.

|`auditId`
|string
|A UUID generated by {registry} for the request. The same value is returned in the `Audit-ID` response header.

|`traceId`
|string
|The OpenTelemetry trace ID of the request, when tracing is enabled and the request has a valid span.

|`stage`
|string
|Always `ResponseComplete`.

|`requestReceivedTimestamp`
|string
|When the request reached the REST layer, in UTC with microsecond precision. For a request rejected before the REST layer's request filters ran, the time of the response.

|`stageTimestamp`
|string
|When the event was written, in UTC with microsecond precision.

|`verb`
|string
|The HTTP method in lower case.

|`requestURI`
|string
|The request path. The query string is not recorded.

|`api`
|string
|The API family: `v2`, `v3`, `ccompat-v7`, `ccompat-v8`, `iceberg-v1`, `mcp-registry-v0.1` or `well-known`.

|`operation`
|string
|The operation ID of the endpoint in the API specification, for example `createArtifactVersion`. For the `/.well-known` endpoints, which have no API specification, the name of the Java method that serves them.

|`user.username`
|string
|The authenticated principal name, or `system:anonymous` for an unauthenticated request.

|`user.groups`
|string array
|The roles of the principal, sorted.

|`sourceIPs`
|string array
|The entries of the `X-Forwarded-For` request header, at most 10, followed by the address of the peer that opened the connection.

|`forwardedFor`
|string
|The `X-Forwarded-For` request header as received.

|`userAgent`
|string
|The `User-Agent` request header.

|`objectRef.resource`
|string
|The last fixed segment of the endpoint path, for example `artifacts`, `versions`, `rules` or `mode`.

|`objectRef.groupId`, `objectRef.artifactId`, `objectRef.version`
|string
|The group, artifact and version the request addressed, taken from the request path. For a successful create, values missing from the path are taken from the identifiers in the response.

|`objectRef.namespace`
|string
|The Apache Iceberg namespace.

|`objectRef.name`
|string
|The identifier of the addressed object when it is not a group, artifact or version, for example a rule type, a Confluent subject, a configuration property name, an Iceberg table or an MCP server name.

|`responseStatus.code`
|integer
|The HTTP status of the response.

|`responseStatus.reason`
|string
|The standard reason for an error status, for example `NotFound` or `Conflict`. Absent for successful responses.

|`outcome`
|string
|`success` for a status below 400, `denied` for 401 and 403, `failure` otherwise.
|===

Apart from the identifiers in `objectRef`, events never contain artifact content, request or response bodies, display names, descriptions, labels, header values other than `X-Forwarded-For` and `User-Agent`, query parameters, exception messages or stack traces.
In every string value, control characters are replaced with `_`, and values longer than 256 characters are cut to 253 characters followed by `...`.

IMPORTANT: The `X-Forwarded-For` header is set by the client or by any proxy on the way, so `sourceIPs` entries before the last one and `forwardedFor` are not trustworthy unless a proxy you control sets the header.

[id="audit-logging-config_{context}"]
== Configuring audit events

:_mod-docs-content-type: REFERENCE

[role="_abstract"]
Audit events are enabled by default.

.Audit event configuration
[%header,cols="2,1,1,4"]
|===
|Property |Type |Default |Description

|`apicurio.audit.enabled`
|boolean
|`true`
|Produce audit events and return the `Audit-ID` header.

|`apicurio.audit.log.enabled`
|boolean
|`true`
|Write the events to the `io.apicurio.registry.audit.events` logger.
|===

The earlier audit log lines, which start with `apicurio.audit action=` and `authz.denied`, are still written in this release, on their existing loggers and in their existing format.
