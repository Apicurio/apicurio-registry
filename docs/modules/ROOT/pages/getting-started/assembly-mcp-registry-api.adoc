[id="mcp-registry-api-overview_{context}"]
== MCP Registry API overview

:_mod-docs-content-type: CONCEPT

[role="_abstract"]
The Model Context Protocol (MCP) Registry API is an experimental {registry} API for publishing and reading MCP server definitions. It is separate from the `mcp/` server module, which exposes {registry} operations as MCP tools.

This Developer Preview targets {registry} 3.4.0. The internal Java package and specification directory use `v0` for the facade generation; the published upstream wire contract is explicitly `v0.1`. They are not separate served API versions.

{registry} stores each published server definition as an artifact of type `MCP_SERVER`. The reverse-DNS server name maps to a group and an artifact ID. For example, `io.github.example/weather` maps to group `io.github.example` and artifact ID `weather`.

== Enabling the MCP Registry API

:_mod-docs-content-type: PROCEDURE

[role="_abstract"]
The MCP Registry API is an experimental feature, so you must enable experimental features and the API itself before {registry} serves it.

.Procedure
* Set both of the following configuration properties:
+
[source,properties]
----
apicurio.features.experimental.enabled=true
apicurio.mcp-registry.enabled=true
----

[id="mcp-registry-api-operations_{context}"]
== MCP Registry API operations

:_mod-docs-content-type: REFERENCE

[role="_abstract"]
The MCP Registry API provides operations to publish a server definition, read and list published server versions, update their status, and soft delete them.

.MCP Registry API operations
[cols="1,2,3",options="header"]
|===
|Operation |Method and path |Behavior

|Publish a server definition
|`POST /apis/mcp-registry/v0.1/publish`
|Maps the reverse-DNS name, for example `io.github.example/weather`, to group `io.github.example` and artifact ID `weather`, with type `MCP_SERVER`. Validates the original JSON against the pinned upstream 2025-12-11 server schema and applies the configured {registry} rules.

|Read a server version
|`GET /apis/mcp-registry/v0.1/servers/\{serverName}/versions/\{version}`
|Returns one published version. The `serverName` path segment is the URL-encoded server name, for example `io.github.example%2Fweather`. Use `latest` as the version to read the most recently published version.

|Read the latest server version
|`GET /apis/mcp-registry/v0.1/servers/\{serverName}`
|Returns the most recently published version of one server. Add `include_deleted=true` to include deleted versions.

|List the versions of a server
|`GET /apis/mcp-registry/v0.1/servers/\{serverName}/versions`
|Returns the published versions of one server, newest first, and HTTP 404 for an unknown server. Accepts the `cursor`, `limit`, and `include_deleted` query parameters.

|List server versions
|`GET /apis/mcp-registry/v0.1/servers`
|Returns all published server versions, newest first. Query parameters filter the list and page through it.

|Update the status of a server version
|`PATCH /apis/mcp-registry/v0.1/servers/\{serverName}/versions/\{version}/status`
|Sets the status of one published version. The JSON body has a required `status` of `active`, `deprecated`, or `deleted`, and an optional `statusMessage` of up to 500 characters. Requires a concrete version, not `latest`. Returns HTTP 400 when the requested status and message match the current ones.

|Update the status of all server versions
|`PATCH /apis/mcp-registry/v0.1/servers/\{serverName}/status`
|Applies the same status update, with the same request body, to every published version of the server. Returns `updatedCount` and the updated `servers`.

|Delete a server version
|`DELETE /apis/mcp-registry/v0.1/servers/\{serverName}/versions/\{version}`
|Soft deletes one published version by setting its status to `deleted` and returns HTTP 200 with the updated record. Requires a concrete version, not `latest`.

|Update a server version
|`PUT /apis/mcp-registry/v0.1/servers/\{serverName}/versions/\{version}`
|Not supported. Returns HTTP 501. Publish a new version instead.
|===

A compatibility rule can protect existing package installation and remote connection choices across versions. Package version and hash upgrades are allowed; removing or changing an existing connection or its configuration is considered backward-incompatible.

.Example read request
[source,shell]
----
curl 'http://localhost:8080/apis/mcp-registry/v0.1/servers/io.github.example%2Fweather/versions/1.0.0'
----

Single-version responses and list entries separate the server definition from registry-owned metadata:

.Example single-version response
[source,json]
----
{
  "server": {
    "name": "io.github.example/weather",
    "version": "1.0.0",
    "description": "Weather forecasts"
  },
  "_meta": {
    "io.modelcontextprotocol.registry/official": {
      "status": "active",
      "isLatest": true
    }
  }
}
----

The following query parameters filter the list of server versions:

`version=latest`:: Selects only the latest version of each server.
`search`:: Matches server names or descriptions.
`updated_since`:: Accepts an RFC 3339 timestamp and compares it with the modification timestamp of the returned version, including status changes. This incremental listing includes deleted records.
`include_deleted=true`:: Includes deleted records in reads that exclude them by default.

To page through results, reuse `metadata.nextCursor` with the same filters. Both explicit and default page limits respect `apicurio.mcp-registry.max-page-size`.

.Example status update request
[source,shell]
----
curl -X PATCH 'http://localhost:8080/apis/mcp-registry/v0.1/servers/io.github.example%2Fweather/versions/1.0.0/status' \
  -H 'Content-Type: application/json' \
  -d '{"status": "deprecated", "statusMessage": "Superseded by version 2.0.0"}'
----

[id="mcp-registry-api-operational-considerations_{context}"]
== MCP Registry API mutation behavior and operational considerations

:_mod-docs-content-type: REFERENCE

[role="_abstract"]
The following behaviors apply when you publish, update, delete, or list MCP server versions through the MCP Registry API.

* Draft artifact versions are not published MCP records, and MCP reads exclude them.
* Version and server-wide status updates persist status messages and update the selected versions atomically. Server-wide updates return `updatedCount` and the updated `servers`.
* DELETE is a soft deletion: it returns HTTP 200 with status `deleted` and retains content and history. Use `include_deleted=true` to inspect a deleted record, or PATCH its status to restore it. Permanent deletion is only available through the native v3 API, subject to `apicurio.rest.deletion.artifact-version.enabled`; MCP does not bypass that gate.
* The optional PUT operation returns HTTP 501, as permitted by the upstream API. Publish a new immutable version instead.
* Input manifests are limited to 1 MiB. Validation uses the bundled schema without fetching the `$schema` URL of the publisher.
* Filtered lists scan and resolve server versions before pagination. The page-size limit bounds responses and storage batches, not total scanning work or memory. Offset cursors do not provide snapshot consistency across concurrent writes.
* GitOps and KubernetesOps storage read from imported branch metadata and reject writes with HTTP 501.
* Registering a server manifest does not contact the server or import its tools.
* Status messages are descriptive, user-editable version metadata. They are not authorization or approval state; {registry} derives the lifecycle status from the version state.
