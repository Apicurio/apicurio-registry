# Registry clients: step-by-step guide

This guide runs one scenario with every client of Apicurio Registry: the Java, Go, Python and
TypeScript SDKs and the CLI. Each step shows what the step does in the REST API, then the same call
in each client, and the line every client prints for it. Follow it on your own, or use it as the
script for a live demo.

**Time:** about 20 minutes. **You will see:**

- how to create a client with each SDK, and how the CLI is configured;
- that the SDKs share one shape, generated by Kiota from the same OpenAPI document: groups,
  artifacts, versions, rules and search are reached the same way in every language;
- how each client reports an error: the HTTP status of a rule violation and of a missing artifact.

For the reference documentation, see *Managing Apicurio Registry content using an SDK*
([source](../../docs/modules/ROOT/pages/getting-started/assembly-using-the-registry-client.adoc)) and
*Managing Apicurio Registry content using the command-line interface*
([source](../../docs/modules/ROOT/pages/getting-started/assembly-managing-registry-artifacts-cli.adoc)).

## Before you start

You need:

- Docker with Docker Compose v2, or Podman with a Compose provider;
- `curl` and `jq`;
- a shell: bash or zsh;
- JDK 21 or later, Go 1.25 or later, Python 3.10 or later and Node.js 22.18 or later. Without one of
  them, skip its clients with `SKIP` (see step 2);
- a free port 8081 (Registry API). If it is in use, see [Using other ports](#using-other-ports).

Run every command from this directory:

```bash
cd examples/registry-clients
```

## Step 1: Start the registry and build the clients

```bash
docker compose up -d --wait
./build.sh
```

`build.sh` builds every client from this checkout, because SDK snapshots are not published: the
Java SDK and the CLI with Maven, the Python SDK into `python-sdk/.venv` (Kiota generates it during
the Python build), and the TypeScript SDK in `typescript-sdk/`, linked into this example. The Go SDK
needs no build step: its generated code is committed, and `go.mod` points to it:

```
replace github.com/apicurio/apicurio-registry/go-sdk/v3 => ../../../go-sdk
```

The first build takes a few minutes. `demo.sh` runs it by itself when a client is not built yet.

## Step 2: Run the scenario with every client

```bash
./demo.sh
```

For each client, `demo.sh` runs the scenario and compares each line it prints with the expected one:

```
Client java:
  ok    java: info ok
  ok    java: created 1
  ok    java: rule BACKWARD
  ok    java: version 2
  ok    java: rejected 400
  ok    java: latest 2
  ok    java: fields id,amount,currency
  ok    java: search 1
  ok    java: deleted
  ok    java: missing 404
Client cli:
  ...
All checks passed.
```

The script is safe to run again: it deletes the group `clients` first, and every client deletes its
own artifact at the end. To leave out clients whose toolchain you do not have:

```bash
SKIP=go,python ./demo.sh
```

To run one client by hand:

```bash
V3=http://localhost:8081/apis/registry/v3
../../mvnw -q exec:java -f java-sdk -Dregistry.url=$V3
(cd go-sdk && go run . $V3 ../schemas)
python-sdk/.venv/bin/python python-sdk/order_scenario.py $V3 schemas
(cd typescript-sdk && node order-scenario.ts $V3 ../schemas)
cli/order-scenario.sh http://localhost:8081 schemas
```

The following steps go through the scenario one step at a time.

## Step 3: Create a client

Every SDK takes the URL of the Core Registry API v3 (`http://localhost:8081/apis/registry/v3`):

```java
// Java: the application owns the Vert.x instance the SDK sends its requests with
Vertx vertx = Vertx.vertx();
RegistryClient client = RegistryClientFactory.create(RegistryClientOptions.create(registryUrl, vertx));
```

```go
// Go
adapter, err := kiotaHttp.NewNetHttpRequestAdapter(&authentication.AnonymousAuthenticationProvider{})
adapter.SetBaseUrl(registryUrl)
client := registry.NewApiClient(adapter)
```

```python
# Python
adapter = HttpxRequestAdapter(AnonymousAuthenticationProvider())
adapter.base_url = registry_url
client = RegistryClient(adapter)
```

```typescript
// TypeScript
const client = RegistryClientFactory.createRegistryClient(registryUrl);
```

The CLI keeps the registry URL, without `/apis/...`, in a context:

```bash
acr context create demo http://localhost:8081
```

`cli/order-scenario.sh` runs the CLI built by `build.sh` (`java -jar
../../cli/target/quarkus-app/quarkus-run.jar`) with its own configuration directory (`ACR_HOME`), so
your own contexts are not changed.

## Step 4: Server information

`GET /system/info`. Every client prints `info ok` when the server reports a version.

```java
client.system().info().get().getVersion()                  // Java
```

```go
info, err := client.System().Info().Get(ctx, nil)          // Go: *info.GetVersion()
```

```python
(await client.system.info.get()).version                   # Python
```

```typescript
(await client.system.info.get())?.version                  // TypeScript
```

```bash
acr version -o json | jq -r '."Server version"'            # CLI
```

## Step 5: Create the artifact

`POST /groups/clients/artifacts` with an artifact ID, the type `AVRO` and
[`order-v1.avsc`](schemas/order-v1.avsc) as its first version. Every client prints `created 1`.

```java
CreateArtifact createArtifact = new CreateArtifact();
createArtifact.setArtifactId("java-sdk-order");
createArtifact.setArtifactType("AVRO");
createArtifact.setFirstVersion(version);    // a CreateVersion with VersionContent: the schema, application/json
client.groups().byGroupId("clients").artifacts().post(createArtifact).getVersion().getVersion();   // "1"
```

```typescript
await client.groups.byGroupId("clients").artifacts.post({
    artifactId: "typescript-sdk-order",
    artifactType: "AVRO",
    firstVersion: { content: { content: schema, contentType: "application/json" } }
});
```

Go and Python build the same `CreateArtifact` model ([`main.go`](go-sdk/main.go),
[`order_scenario.py`](python-sdk/order_scenario.py)).

```bash
acr artifact create cli-order -g clients -f schemas/order-v1.avsc --type AVRO
```

`acr artifact create` prints the artifact's metadata, but not the version it created, so the script
reads it back with `acr artifact version get -g clients -a cli-order branch=latest -o json`.

## Step 6: Add a compatibility rule

`POST /groups/clients/artifacts/<id>/rules` with `{"ruleType": "COMPATIBILITY", "config":
"BACKWARD"}`, then `GET .../rules/COMPATIBILITY`. Every client prints `rule BACKWARD`.

```python
rule = CreateRule()
rule.rule_type = RuleType.COMPATIBILITY
rule.config = "BACKWARD"
await artifact.rules.post(rule)
(await artifact.rules.by_rule_type("COMPATIBILITY").get()).config    # "BACKWARD"
```

```bash
acr artifact rule create -g clients -a cli-order COMPATIBILITY -c BACKWARD
acr artifact rule get -g clients -a cli-order COMPATIBILITY -o json
```

`BACKWARD` means that consumers using the new schema can read data written with the previous one.

## Step 7: Add a compatible version

`POST /groups/clients/artifacts/<id>/versions` with [`order-v2.avsc`](schemas/order-v2.avsc), which
adds a field with a default: `{"name": "currency", "type": "string", "default": "EUR"}`. The rule
accepts it, and every client prints `version 2`.

```go
v2, err := art.Versions().Post(ctx, version("order-v2.avsc"), nil)   // *v2.GetVersion() == "2"
```

```bash
acr artifact version create -g clients -a cli-order -f schemas/order-v2.avsc
```

## Step 8: An incompatible version is rejected

[`order-v3-incompatible.avsc`](schemas/order-v3-incompatible.avsc) adds `customer` without a
default: data written with version 2 has no value for it, so the `BACKWARD` rule rejects it. The REST
API answers 400 with a problem whose `ruleViolation` lists the causes:

```json
{"status": 400, "name": "RuleViolationException",
 "detail": "Incompatible artifact: ... [customer at /fields/3] ...",
 "ruleViolation": {"ruleType": "COMPATIBILITY", "causes": [{"description": "customer", "context": "/fields/3"}]}}
```

Each SDK raises it as an error that carries the HTTP status, and every client prints
`rejected 400`:

| Client | The error | Its status |
|--------|-----------|------------|
| Java | `RuleViolationProblemDetails` for a 400, `ProblemDetails` otherwise; both are a Kiota `ApiException` | `getResponseStatusCode()` |
| Go | an `error` that `errors.As` turns into `abstractions.ApiErrorable` | `GetStatusCode()` |
| Python | `APIError` | `response_status_code` |
| TypeScript | the rejected promise's error | `responseStatusCode` |

The CLI prints the detail and the causes, and exits with code 3, as for any server error:

```
$ acr artifact version create -g clients -a cli-order -f schemas/order-v3-incompatible.avsc
Error: Incompatible artifact: cli-order [AVRO], num of incompatible diffs: {1}, list of diff types: [customer at /fields/3] Causes: customer at /fields/3
  -> /fields/3: customer
```

It does not print the HTTP status, so the script reads it from the HTTP log that `--verbose` writes
to stderr (`< 400 Bad Request`).

## Step 9: Read the latest version

`GET .../versions/branch=latest` and `GET .../versions/branch=latest/content`. The rejected version
was not stored, so the latest is version 2, with version 2's fields. Every client prints `latest 2`
and `fields id,amount,currency`.

```typescript
const latest = artifact.versions.byVersionExpression("branch=latest");
(await latest.get())?.version;                                       // "2"
JSON.parse(new TextDecoder().decode(await latest.content.get()));   // the schema
```

```bash
acr artifact version get -g clients -a cli-order branch=latest -o json
acr artifact version get -g clients -a cli-order branch=latest --content
```

## Step 10: Search

`GET /search/artifacts?groupId=clients&artifactId=<id>`. Every client prints `search 1`.

```java
client.search().artifacts().get(r -> {
    r.queryParameters.groupId = "clients";
    r.queryParameters.artifactId = "java-sdk-order";
}).getCount();
```

```bash
acr search artifact -g clients -a cli-order -o json
```

## Step 11: Delete the artifact

`DELETE /groups/clients/artifacts/<id>`, then `GET` it: 404. Every client prints `deleted` and
`missing 404`. The registry only allows deletions when they are enabled, as
[`docker-compose.yml`](docker-compose.yml) does (`apicurio.rest.deletion.artifact.enabled`).

```python
await artifact.delete()
await artifact.get()      # raises APIError, response_status_code 404
```

```bash
acr artifact delete cli-order -g clients
```

## Step 12: Clean up

```bash
docker compose down -v
```

## Presenter notes

- **Before the session:** run steps 1 and 2 in advance, so the image is downloaded and the clients
  are built.
- **The story in one sentence per step:** one OpenAPI document; five clients generated from it or
  built on it; the same scenario gives the same answers in each; when one differs, `demo.sh` fails.
- **Questions that usually come up:**
  - *Why is the rule violation a 400 and not a 409?* Since 3.3.0 the v3 API answers 400; set
    `apicurio.rest.legacy-error-codes.enabled=true` for the former 409.
  - *Which SDK version should I use?* The one matching your registry's major version (3.x); the SDKs
    are released with the registry.
  - *How do I authenticate?* See the [authentication example](../authentication/): OAuth2 and HTTP
    basic with the Java SDK and the CLI.
- **To reset between runs:** `./demo.sh` resets its own data; `docker compose down -v` resets
  everything.

## Troubleshooting

| Symptom | What to do |
|---|---|
| `demo.sh` times out waiting for the Registry | Check `docker logs apicurio-registry-api-clients`. Usually a port conflict: see [Using other ports](#using-other-ports). |
| `The go client needs 'go', which is not installed.` | Install the toolchain, or skip the client: `SKIP=go ./demo.sh`. |
| `build.sh failed` | `demo.sh` prints the end of the build log. Run `./build.sh` to see all of it; `SKIP=...` builds only the other clients. |
| A client prints `FAIL ... (expected ...)` after an SDK change | The SDK now behaves differently from the others. Run the client by hand (step 2) to see its output and errors. |
| Every CLI command takes several seconds | That is JVM startup, and on macOS often a slow lookup of the local host name (add it to `/etc/hosts`). An installed native `acr` avoids the JVM: run the script with `ACR=acr`. |

## Using other ports

If port 8081 is in use, choose another, and tell both Compose and `demo.sh`:

```bash
export REGISTRY_PORT=18081
docker compose up -d --wait
API=http://localhost:$REGISTRY_PORT/apis ./demo.sh
```
