# Registry clients

The same scenario, run with every client of Apicurio Registry, built from this checkout:

- **[Java SDK](java-sdk/)** ([`java-sdk/`](../../java-sdk/), generated by Kiota, published to Maven
  Central as `io.apicurio:apicurio-registry-java-sdk`).
- **[Go SDK](go-sdk/)** ([`go-sdk/`](../../go-sdk/), module
  `github.com/apicurio/apicurio-registry/go-sdk/v3`).
- **[Python SDK](python-sdk/)** ([`python-sdk/`](../../python-sdk/), `apicurioregistrysdk` on PyPI).
- **[TypeScript SDK](typescript-sdk/)** ([`typescript-sdk/`](../../typescript-sdk/),
  `@apicurio/apicurio-registry-sdk` on npm).
- **[The CLI](cli/)** (`acr`, [`cli/`](../../cli/), a dev preview).

Each client creates an Avro schema, protects it with a compatibility rule, evolves it, has an
incompatible change rejected, reads, searches and deletes it, and prints one line per step.
`demo.sh` checks that every client prints the same lines, so a client that behaves differently from
the others, or from the REST API, fails the example.

**New to this? Follow the [step-by-step guide](GUIDE.md).** It walks through each step and shows
the code for it in every client, in about 20 minutes.

## Quick start

Requires Docker (or Podman) with Compose v2, `curl`, `jq`, and the toolchain of each client: JDK 21
or later (Java SDK and CLI), Go 1.25 or later, Python 3.10 or later, and Node.js 22.18 or later.

```bash
docker compose up -d     # starts the Registry
./demo.sh                # builds the clients (first run only), then runs the scenario with each
```

`demo.sh` prints one line per check and ends with `All checks passed.` (it exits non-zero if a check
fails). The first run builds the clients with [`build.sh`](build.sh), which takes a few minutes; run
`./build.sh` again after changing an SDK.

Missing a toolchain? Skip its clients: `SKIP=go,python ./demo.sh` (the names are `java`, `cli`,
`go`, `python` and `typescript`). In CI (`CI=true`) nothing can be skipped.

Stop and remove everything with `docker compose down -v`.

## The scenario

Every client works in the group `clients`, with an artifact of its own (`java-sdk-order`,
`cli-order`, `go-sdk-order`, `python-sdk-order`, `typescript-sdk-order`), and prints:

| Step | Line | What it checks |
|------|------|----------------|
| 1 | `info ok` | The server information has a version |
| 2 | `created 1` | The AVRO artifact is created, with [`order-v1.avsc`](schemas/order-v1.avsc) as version 1 |
| 3 | `rule BACKWARD` | A `COMPATIBILITY` rule set to `BACKWARD` on the artifact, read back |
| 4 | `version 2` | [`order-v2.avsc`](schemas/order-v2.avsc), a new field with a default, is accepted as version 2 |
| 5 | `rejected 400` | [`order-v3-incompatible.avsc`](schemas/order-v3-incompatible.avsc), a new field without a default, is rejected with HTTP 400, a rule violation |
| 6 | `latest 2`, `fields id,amount,currency` | The latest version is 2, and its content has version 2's fields |
| 7 | `search 1` | Searching by group and artifact ID finds it |
| 8 | `deleted`, `missing 404` | The artifact is deleted, and reading it then returns 404 |

Since 3.3.0 the REST API rejects a rule violation with 400; it was 409 before, and still is with
`apicurio.rest.legacy-error-codes.enabled=true`.

## Notes

- **Built from this checkout:** snapshots of the SDKs are not published, so `build.sh` builds the
  Java SDK and the CLI with Maven, generates the Python SDK while installing it (Kiota runs during
  the Python build, in `python-sdk/`), and generates and builds the TypeScript SDK in
  `typescript-sdk/`. The Go SDK's generated code is committed, so `go run` compiles it. To use the
  released SDKs instead, depend on them as usual (see [Learn more](#learn-more)): the code does not
  change.
- **The CLI runs on the JVM:** `build.sh` builds it with `-DcliSkipNative`, and
  [`cli/order-scenario.sh`](cli/order-scenario.sh) runs `java -jar cli/target/quarkus-app/quarkus-run.jar`
  with a configuration directory of its own (`ACR_HOME`), so it does not touch your contexts. Set
  `ACR=acr` to run an installed CLI instead.
- **What the CLI does differently:** `acr artifact create` prints the artifact's metadata but not
  the version it created, so the script reads version 1 back. The CLI exits with code 3 on any
  server error and prints the problem's detail, not the HTTP status, so the script reads the status
  from the HTTP log of `--verbose`.
- **Other ports:** if 8081 is in use, see [Using other ports](GUIDE.md#using-other-ports).
- **Local build:** the example uses the `latest-snapshot` image. To run a locally built registry,
  build it (`./mvnw install -pl distro/docker -am -DskipTests`), build
  `distro/docker/target/docker/Dockerfile.jvm` as an image, and start the example with
  `REGISTRY_IMAGE=<that image> docker compose up -d`.
- **Local only:** in-memory storage and no authentication. For authenticated clients (OAuth2 and
  HTTP basic, with the Java SDK, the serdes, the Maven plugin and the CLI), see the
  [authentication example](../authentication/).
- **Replaces** the former `rest-client` (Java SDK) and `sdk/go-sdk` examples.
