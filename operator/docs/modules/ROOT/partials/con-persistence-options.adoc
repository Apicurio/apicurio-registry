= {registry} storage options

The main decision to make when deploying {registry} is which storage backend to use.

The following storage options are available:

.{registry} data storage options
[%header,cols="1,3"] 
|===
|Storage option
|Description

ifdef::apicurio-registry[]
|In-memory
|Data is stored in RAM on each {registry} node. This is the easiest deployment to use, but is not recommended for production environment. All data is lost when restarting {registry} with this storage option, which is suitable for a development environment only. 
endif::[]

|SQL database  
|Data is stored in a relational database, in this case PostgreSQL 12+. This is the recommended storage option in a production environment for performance, stability, and data management (backup/restore, and so on).

ifdef::apicurio-registry[]
|Apache Kafka 
endif::[]
ifdef::service-registry[]
|{kafka-streams} 
endif::[]
|Data is stored using Apache Kafka, with the help of a local SQL database on each node. This storage option is provided for production environments where database management expertise is not available, or where storage in Kafka is a specific requirement.
|===


ifdef::apicurio-registry[]
.Storage requiring installation
The following options require that the storage is already installed as a prerequisite:

* SQL (PostgreSQL)
* Apache Kafka
endif::[]

ifdef::service-registry[]
These options require that the storage is already installed as a prerequisite.
endif::[]

[id="registry-persistence-storage-migration"]
== Migrating from deprecated storage fields

The top-level fields `spec.app.sql` and `spec.app.kafkasql` were deprecated in {operator} 3.0.7
and *removed in 3.3.2*. Between 3.0.7 and 3.3.1 the operator migrated them to `spec.app.storage`
automatically. From 3.3.2 onward they are no longer part of the `ApicurioRegistry3` CRD, they are
not accepted, and storage must be configured under `spec.app.storage`.

.Before (removed)
[source,yaml]
----
spec:
  app:
    sql:
      dataSource:
        url: jdbc:postgresql://postgresql:5432/apicurio
        username: apicurio
        password: password
----

.After (required)
[source,yaml]
----
spec:
  app:
    storage:
      type: postgresql
      sql:
        dataSource:
          url: jdbc:postgresql://postgresql:5432/apicurio
          username: apicurio
          password:
            name: postgresql-credentials
            key: password
----

NOTE: The password field shape also changed. The deprecated `app.sql.dataSource.password`
accepted a plaintext string; `app.storage.sql.dataSource.password` is a reference to a
Kubernetes Secret. `name` is the name of the Secret and is required. `key` is optional and
defaults to `password`, so it can be omitted when the Secret uses that key.

For KafkaSQL, replace `spec.app.kafkasql` with `spec.app.storage.type: kafkasql` and
`spec.app.storage.kafkasql`.

IMPORTANT: Existing custom resources that still use `spec.app.sql` or `spec.app.kafkasql` must be
updated *before* upgrading to 3.3.2 or later. Automatic migration of those fields is no longer
performed, and upgrading without updating them disconnects Registry from its configured database
without reporting an error. See the upgrade failure mode below.

.Upgrade failure mode
After this removal, `spec.app.sql` and `spec.app.kafkasql` are no longer part of the
`ApicurioRegistry3` CRD/`AppSpec` model. On upgrade, those fields are silently dropped rather
than migrated. The operator configures SQL and KafkaSQL storage only from `spec.app.storage`; if
that is absent, it sets no storage environment variables at all and Registry falls back to its
default embedded H2 database. That database is ephemeral: its contents are lost whenever the pod
restarts.
There is currently no dedicated status condition that reports the removed fields, so this failure
is silent. After upgrading, verify that `spec.app.storage` is set and that Registry is not
unexpectedly running on the embedded database.

See also issue https://github.com/Apicurio/apicurio-registry/issues/7317[Apicurio Registry #7317]
and the corresponding release notes for this breaking change.
